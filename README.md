# pos_fontend

ফার্মেসি ও কসমেটিক্স দোকানের মোবাইল-প্রথম POS। Next.js (App Router) + TypeScript + Tailwind, স্ট্যাটিক export করা PWA।
ব্যাকএন্ড: [`pos_backend`](https://github.com/showmik121/pos_backend) (Supabase Edge Function + PostgreSQL)।

## এখন যা কাজ করে

- **দোকান ও লগইন:** দোকান খোলা, লগইন/লগআউট, কর্মচারী যোগ/বন্ধ (শুধু মালিক)
- **পণ্য ও স্টক:** পণ্য যোগ/বদল, বারকোড (কার্টন সহ), ব্যাচ ও মেয়াদ, স্টক জমা, CSV ইমপোর্ট, মেয়াদ অ্যালার্ট, মেয়াদোত্তীর্ণ ব্যাচ কারণসহ সরানো (ক্ষতির খাতা)
- **বিক্রি:** স্ক্যানার (ক্যামেরা বা হাতে নম্বর), FIFO ব্যাচ থেকে বিক্রি, ছাড়, নগদ ও মোবাইল পেমেন্ট, বাকিতে বিক্রি, রসিদ (প্রিন্ট/শেয়ার), বিল বাতিল
- **বাকির খাতা:** কাস্টমার, বাকি আদায়, কাস্টমারভিত্তিক খাতা
- **রিপোর্ট:** দৈনিক সারাংশ, সেরা পণ্য
- **সিংক:** সব বদল ইভেন্ট হয়ে সার্ভারে যায় ও অন্য ফোনের বদল আসে; অফলাইনে ফোনে জমে, নেট এলে নিজে থেকে যায় (বিল নম্বর "A-১০০১" ডিভাইস-উপসর্গসহ)
- **নিরাপদ রাখা:** ব্যাকআপ নামানো/ফেরানো, ব্যাকআপ-স্মরণ, স্থায়ী স্টোরেজের অনুরোধ, ক্র্যাশ স্ক্রিনে ডেটার কপি, লগআউটে "ডেটা মুছুন"
- **PWA:** ম্যানিফেস্ট, আইকন, service worker (পেজ ও স্ট্যাটিক ফাইল অফলাইনে খোলে; ক্যাশ সীমাবদ্ধ)
- **ক্র্যাশ রিপোর্ট:** অ্যাপ ভাঙলে নিজের সার্ভারে জানায় (ফোন নম্বরের মতো সংখ্যা আড়াল করে)
- পুরো UI বাংলায়; মোবাইল নম্বর বাংলা বা ইংরেজি অঙ্কে লেখা যায়

আসল ফোনে ম্যানুয়াল পরীক্ষা এখনো বাকি; বিস্তারিত সীমা `CLAUDE.md`-র "জানা সীমাবদ্ধতা"-য়।

## চালানো

```bash
npm install
npm run dev        # http://localhost:3000
```

ডিফল্টে লাইভ ব্যাকএন্ডে যায়। অন্য ঠিকানা লাগলে `.env.example` কপি করে `.env.local` বানিয়ে `NEXT_PUBLIC_API_URL` বদলান।

> লোকালে `localhost:3000` থেকে লগইন চলবে কারণ ব্যাকএন্ডের `ALLOWED_ORIGINS`-এ সেটি আছে। অন্য ঠিকানা (হোস্ট করা সাইট) থেকে চালালে সেই ঠিকানা ব্যাকএন্ডের `ALLOWED_ORIGINS` secret-এ যোগ করতে হবে, নইলে ব্রাউজার (CORS) আটকাবে।

## কমান্ড

| কমান্ড | কাজ |
| --- | --- |
| `npm run dev` | ডেভ সার্ভার |
| `npm run build` | স্ট্যাটিক সাইট তৈরি (`out/`) |
| `npm run typecheck` | TypeScript যাচাই |
| `npm run lint` | ESLint (Next.js ও TypeScript নিয়ম) |
| `npm test` | Vitest টেস্ট |
| `npm run test:e2e` | Playwright E2E (আগে `NEXT_PUBLIC_API_URL=/api npm run build`) |

CI (GitHub Actions) প্রতি পুশে typecheck, lint, test, build, নির্ভরতার নিরাপত্তা-যাচাই (`npm audit`) ও দুই ধরনের E2E (নকল ও আসল ব্যাকএন্ড) চালায়।

```
src/lib/store/     স্থানীয় ডেটা: types, actions, selectors, backup, csv
src/lib/sync/      সিংক: ইভেন্ট, রিপ্লে, diff, seed, ইঞ্জিন
src/lib/api/       API ক্লায়েন্ট, zod স্কিমা, এন্ডপয়েন্ট
src/lib/report/    ক্র্যাশ রিপোর্ট

```

## নিরাপত্তার নোট

- সেশন টোকেন `localStorage`-এ থাকে (ব্যাকএন্ডে টোকেনের মেয়াদ এখন ১২ ঘণ্টা)। হোস্ট করার সময় CSP হেডার দিন।
- পাসওয়ার্ড কোথাও সংরক্ষিত হয় না; শুধু API-তে HTTPS-এ যায়।

## ডেটা কোথায় থাকে

লগইন, দোকান ও কর্মচারী সরাসরি সার্ভারে (Supabase)। পণ্য, স্টক, বিল ও বাকির খাতা **আগে ফোনের ব্রাউজারে** (`localStorage`, দোকান অনুযায়ী আলাদা) সেভ হয়, তারপর সিংক ইভেন্ট হয়ে সার্ভারের ইভেন্ট-লগে যায়। অফলাইনেও সব কাজ চলে। তবু ব্যাকআপ নেওয়া ভালো (সেটিংস থেকে)। সব হিসাব পয়সায় (পূর্ণসংখ্যা), স্টক পিসে।
