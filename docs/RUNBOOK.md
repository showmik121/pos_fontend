# রানবুক: ফ্রন্টএন্ড (Netlify)

কিছু ভাঙলে এই পাতা দেখুন। ব্যাকএন্ড ও ডেটাবেসের জন্য `pos_backend/docs/RUNBOOK.md`। পুরো সিস্টেমের সীমাবদ্ধতা `POS_SYSTEM/docs/KNOWN_LIMITATIONS.md`-তে।

**চিহ্ন:** ✅ = প্রমাণসহ যাচাই হয়েছে · ⚠ = লেখা আছে কিন্তু কেউ চালিয়ে দেখেননি · ❌ = নেই/ভাঙা।

## ১. কোথায় কী চলছে
- সাইট: Netlify, `https://bipone.netlify.app/`। `main`-এ পুশ হলে নিজে বিল্ড ও প্রকাশ হয়।
- বিল্ড সেটিং `netlify.toml`-এ: `npm run build`, প্রকাশ `out/`, Node ২২। নিরাপত্তা হেডার `public/_headers`-এ (✅ লাইভে হেডার পৌঁছাচ্ছে: ২০২৬-১১-২০-এ `curl -I` দিয়ে CSP, HSTS, X-Frame-Options, nosniff দেখা গেছে)।
- কোনো গোপন তথ্য ফ্রন্টএন্ডে নেই। একমাত্র ভেরিয়েবল `NEXT_PUBLIC_API_URL` (না দিলে লাইভ API ধরা হয়)।
- ফন্ট (Noto Sans Bengali) এখন প্যাকেজ থেকে আসে (`@fontsource/noto-sans-bengali`); বিল্ডে বাইরের কোনো সাইটে ডাক নেই (✅ বিল্ড-আউটপুটে Google Fonts-এর উল্লেখ ০টি)। `package-lock.json` কমিট করা আছে; CI ও বিল্ড `npm ci` চালায়।
- **ব্যবহারকারীর ব্যবসার ডেটার আসল কপি ফোনের ব্রাউজারে** (পণ্য, স্টক, বিল, বাকি)। সার্ভারে যায় সিংক-ইভেন্টের লগ হিসেবে (৫ নম্বর), কিন্তু সার্ভারে এখনো রিপোর্ট/ফেরানোর মতো গঠিত টেবিল নেই। তাই ফোনের ব্যাকআপই মূল ব্যাকআপ (৪)।

## ২. খারাপ সংস্করণ ছড়িয়ে গেলে (কোড rollback)
**দ্রুততম (১ মিনিট), কোড না ছুঁয়ে:**
1. Netlify → সাইট → **Deploys** → আগের ভালো ডিপ্লয় বাছুন → **Publish deploy**।
2. এতে Netlify নতুন ডিপ্লয় আটকে রাখে (auto-publish বন্ধ)। ঠিক করে পুশ করার পর **Start auto publishing** চালু করুন।

**স্থায়ী সমাধান:** `git revert <খারাপ কমিট>` করে `main`-এ পুশ। CI (টাইপ, লিন্ট, টেস্ট, বিল্ড, E2E) পাস হলে Netlify আবার প্রকাশ করবে।

ফোনে পুরনো পাতা আটকে থাকলে: অ্যাপ পুরো বন্ধ করে আবার খুলুন। সার্ভিস ওয়ার্কার (`public/sw.js`) নতুন সংস্করণ নিজে নেয়। ক্যাশ-কৌশল বদলালে `sw.js`-এর `VERSION` বাড়ান।

**ডিপ্লয়ের ক্রম:** সিংকের নিয়ম বদলালে আগে ফ্রন্টএন্ড, পরে ব্যাকএন্ড (ব্যাকএন্ড রানবুক ২-এর ধাপ ৫)। ফোনের পুরনো ক্যাশ-করা কপি নতুন ব্যাকএন্ডের নিয়মে আটকাতে পারে; এ কারণেই এই ক্রম।
- ⚠ Netlify ধাপগুলো ড্যাশবোর্ডের বর্তমান লেখার সাথে হাতে মেলানো হয়নি; লেবেল বদলে থাকতে পারে।

## ৩. বিল্ড ফেল করলে
- Netlify → Deploys → ফেল হওয়া ডিপ্লয় → লগ।
- টাইপ, লিন্ট বা টেস্ট ফেল হলে GitHub Actions-এ একই ধাপ ফেল দেখাবে; সেখান থেকে ঠিক করুন।
- `npm ci` ফেল করলে সাধারণত `package.json` ও `package-lock.json` মিলছে না: লোকালে `npm install` চালিয়ে লকফাইলসহ কমিট করুন।
- ✅ পরিষ্কার ক্লোনে (`git clone` → `npm ci` → typecheck → lint → test → build) সব ধাপ ২০২৬-১১-২০-এ এক চেষ্টায় পাস (প্রমাণ: `POS_SYSTEM/docs/handover-evidence/`)। আগে `next/font/google`-এর নেটওয়ার্ক-ডাকে বিল্ড এলোমেলো ভাঙত; সেটি সরানো হয়েছে।
- **Windows Git Bash-এ** `NEXT_PUBLIC_API_URL=/api npm run build` চালাবেন না: MSYS `/api`-কে `C:/Program Files/Git/api` বানিয়ে ফেলে, ফলে সব API-ডাক ব্যর্থ হয়। PowerShell-এ (`$env:NEXT_PUBLIC_API_URL="/api"`) বা `MSYS_NO_PATHCONV=1` দিয়ে চালান।
- Windows-এ গোল্ডেন-ফিক্সচার টেস্ট আগে CRLF-এ ফেল করত; `.gitattributes` এখন ফিক্সচার LF রাখে (✅ ২০২৬-১১-২০ ক্লোন-পরীক্ষায় ২৩৫/২৩৫ পাস)।

## ৪. ফোনের ডেটা (সবচেয়ে গুরুত্বপূর্ণ)
**ব্যাকআপ:** সেটিংস → "ব্যাকআপ ফাইল নামান"। অ্যাপ দিনে একবার (কিছু বদলালে) মনে করায়। ফাইলটি Google Drive বা অন্য ফোনে রাখুন। ফাইলে গ্রাহকের নাম-ফোন, বিক্রি, বাকি সবই সাধারণ লেখায় (এনক্রিপ্ট করা নয়): নিরাপদে রাখুন।

**ফেরানো:** সেটিংস → "ব্যাকআপ থেকে ফেরান" → ফাইল বাছুন → নিশ্চিত করুন। শুধু **একই দোকানের** ব্যাকআপ ফেরানো যায় (অন্য দোকানের ফাইল আটকে যায়)।
- ✅ ব্যাকআপ → ডেটা মোছা → ফেরানো প্রবাহ স্বয়ংক্রিয় E2E-তে যাচাই (`e2e/critical-flows.e2e.ts`): পণ্য, স্টক, বিল, বাকির খাতা ফিরেছে; অন্য দোকানের ও নষ্ট ফাইল আটকেছে।
- ফেরালে ফোনের বর্তমান ডেটা ব্যাকআপের ডেটা দিয়ে বদলে যায়। আগে এখনকার অবস্থার একটি ব্যাকআপ নিয়ে রাখুন।
- ডিভাইস কোড (A–Z) ব্যাকআপে থাকে না; নতুন ফোনে লগইন করলে সার্ভার নতুন কোড দেবে।

**অ্যাপ ভেঙে গেলে:** ত্রুটি পাতায় "ডেটার কপি নামান" চাপুন। ডেটা নষ্ট থাকলে `pos-raw-তারিখ.json` নামে কাঁচা ফাইল নামবে; ডেভেলপারকে দিন।

**ফোন বদল বা মুছে গেলে:** সর্বশেষ ব্যাকআপ ফেরান। এর বাইরে: সিংক চালু থাকলে সার্ভারে প্রতিটি বদলের ইভেন্ট জমা আছে; নতুন ফোনে লগইন করলে সেই ইভেন্ট নেমে এসে ডেটা গড়ে ওঠার কথা (রিপ্লে-যুক্তি ইউনিট-টেস্টে যাচাই)। ⚠ দ্বিতীয় আসল ফোনে এই "সার্ভার থেকে পুনর্গঠন" শুরু-থেকে-শেষ কেউ চালিয়ে দেখেননি; এর ওপর ভরসা করার আগে একবার পরীক্ষা করুন।

## ৫. সিংক: কী দেখাচ্ছে, মানে কী
সেটিংসে "সিংক" বার্তা:
| বার্তা | মানে | করণীয় |
|---|---|---|
| "সার্ভারে সিংক আছে (সর্বশেষ …)" | সব বদল সার্ভারে পৌঁছেছে | কিছু না |
| "N টি বদল সার্ভারে পাঠানো বাকি" | অফলাইনে জমে আছে, নেট এলে নিজে যাবে | অপেক্ষা; ডেটা ফোনে নিরাপদ |
| "সিংক থেমে আছে — লগআউট করে আবার লগইন করুন" | টোকেন/ডিভাইস সমস্যা (৪০১) | লগআউট (ডেটা ফোনে রেখে) → লগইন |
| "N টি বদল সার্ভার নেয়নি" | সার্ভার ওই ইভেন্টগুলো বারবার ফেরত দিয়েছে | ব্যাকআপ নিন, ডেভেলপারকে জানান |
- কর্মচারীর সেশনে মালিক-মাত্র ইভেন্ট (বিল বাতিল, সেটিংস, ব্যাচ সরানো) কিউতে আটকে থাকে, বাদ যায় না; মালিক ওই ফোনে সিংক চালালে যায়। তাই কর্মচারীর ফোনে "পাঠানো বাকি" গোনা কিছু থেকে যেতে পারে।
- অন্য ডিভাইস থেকে আসা বিকৃত ইভেন্ট বাদ যায় (সিংক আটকায় না); ✅ ইউনিট-টেস্টে যাচাই।
- ✅ অফলাইনে বিক্রি → নেট এলে একবারই সার্ভারে যাওয়া E2E-তে যাচাই (নকল সার্ভারে)। ⚠ আসল সার্ভার ও দুই আসল ফোনে এটি যাচাই হয়নি।
- জানা সীমা: দুই ফোনে একই ব্যাচ থেকে বেশি বিক্রি হলে ব্যাচের স্টক ঋণাত্মক হতে পারে (নীরবে; কোনো সতর্কতা নেই)।

## ৬. ভূমিকা (মালিক বনাম কর্মচারী)
- কর্মচারী পারে না: বিল বাতিল, লাভের রিপোর্ট দেখা, কর্মচারী-ব্যবস্থাপনা, ব্যাচ সরানো (✅ E2E-তে যাচাই)।
- ❌ **কর্মচারী ক্রয়মূল্য দেখতে পায়** (পণ্যের বিবরণ, সম্পাদনা, স্টক-জমার ফর্ম) এবং সিংক-ইভেন্ট থেকেও পড়তে পারে। ব্যাকএন্ডের REST এটি লুকায়, ফোনের UI ও সিংক লুকায় না। যদি ক্রয়মূল্য গোপন রাখা ব্যবসার শর্ত হয়, এটি হস্তান্তরের আগে সমাধান করুন (`POS_SYSTEM/docs/KNOWN_LIMITATIONS.md`)।
- ❌ ফোনের ঘড়ি পেছালে মেয়াদোত্তীর্ণ ব্যাচ আবার বিক্রি-যোগ্য হয়ে যায় (ঘড়ি-পাহারা নেই)।

## ৭. পরীক্ষা চালানো
```bash
npm ci
npm run typecheck && npm run lint && npm test          # ইউনিট: ২৩৫টি
npx playwright install chromium                         # প্রথমবার
NEXT_PUBLIC_API_URL=/api npm run build                  # (Windows Git Bash নয়, ৩ নম্বর দেখুন)
npm run test:e2e                                        # ১২টি পাস, ১টি বাদ (আসল ব্যাকএন্ড লাগে: E2E_REAL=1)
```
- দুটি জানা ত্রুটি `test.fail` চিহ্নিত; `E2E_EXPECT_FIXED=1 npx playwright test` চালালে সেগুলোর আসল ব্যর্থতা দেখায়।
- ৩৭৫px-এ সব পাতা ঘোরার টেস্ট (`e2e/qa-375.e2e.ts`) ছবি ও `findings.json` লেখে (`QA_OUT` পরিবেশ-চলকে ঠিক করুন)।

## ৮. ঘটনা ঘটলে প্রথম ১০ মিনিট
1. কী ভেঙেছে? শুধু একটি ফোনে (ডেটা/ব্রাউজার সমস্যা) না সবার (সাইট/API)?
2. সবার ক্ষেত্রে: `https://gaxzkbcomeexlnzquvzf.supabase.co/functions/v1/api/health` খুলুন। `{"status":"ok"}` না এলে ব্যাকএন্ড রানবুক দেখুন। (⚠ ২০২৬-১১-২০-এ শুধু `{"status":"ok"}` এসেছে, `db` ফিল্ড ছাড়া; ব্যাকএন্ড রানবুক ১ দেখুন।)
3. সাইট ভাঙলে ২ নম্বর (Publish deploy)।
4. ব্যবহারকারীকে বলুন: "ডেটা আপনার ফোনে নিরাপদ, ব্যাকআপ নিয়ে রাখুন।"
5. কারণ লিখে রাখুন এবং ঠিক হলে একটি টেস্ট ও কমিট যোগ করুন।
